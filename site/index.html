01 / PROTOKOL VS IMPROVISASI

Mengapa AI Agent Membutuhkan Hukum Besi

Seperti Raja Viserys yang menjaga perdamaian kerajaan melalui suksesi dan tatanan tertulis, proyek perangkat lunak membutuhkan artefak kebenaran tunggal agar subagent tidak berhalusinasi di tengah jalan.

Tanpa Viserys (Vibe Coding)

Improvisasi Tanpa Kontrak

  • Asumsi buta pada prompt pertama: Agent langsung membuat puluhan file tanpa menanyakan siapa pengguna utama, batasan performa, atau aturan autentikasi.
  • Task monolitik yang gagal di tengah: Seluruh fitur dikerjakan dalam satu giliran raksasa. Saat terjadi error, agent menimpa file yang sudah benar.
  • Tampilan UI generik (AI Slop): Gradien ungu-biru tanpa alasan, kartu fitur seragam, tombol mati yang tidak berfungsi, dan kontras warna yang gagal dibaca.
Disiplin Viserys

Tiga Pilar Rekayasa Terukur

  • Wawancara Pohon Keputusan (get-prd): Menggali niat asli lewat 1 pertanyaan tajam per giliran hingga tingkat keyakinan mencapai 85%, lalu mengunci spesifikasi di docs/PRD.md.
  • Irisan Vertikal & Gate TDD (get-tasks): Memecah PRD menjadi tasks/<feature>/plan.md dan task-*.md lengkap dengan urutan blokir dan perintah tes otomatis.
  • Spesifikasi Desain Anti-Slop (get-design): Menetapkan sistem token, tipografi berkarakter, state interaktif lengkap (kosong, muat, galat), dan kontras WCAG di docs/design.md.

ISI FILE KELUARAN docs/PRD.md 
# PRD: Retail Counter Inventory Ledger

## 1. Problem Statement
Kasir toko ritel kecil sering mengalami selisih stok fisik karena pencatatan barang masuk dan keluar terpisah dari meja transaksi dan gagal tersimpan saat koneksi internet tidak stabil.

## 2. Target User & Operating Context
- Pengguna Utama: Kasir toko di meja pembayaran.
- Perangkat: Desktop browser (1280px+) dengan pemindai barcode USB (keyboard wedge).

## 3. Core Data & Entity Model
| Entity | Key Attributes | Relationships |
|---|---|---|
| Product | id (uuid), barcode (unique), name, min_stock | 1-to-many StockEntries |
| StockEntry | id, product_id, delta_qty, reason, synced_at | belongs-to Product |
| LocalQueue | id, payload_json, retry_count, status | 1-to-1 StockEntry |

## 4. Non-Functional Requirements (NFRs)
- Pencarian barcode lokal wajib selesai di bawah 50ms (IndexedDB cache).
- Mutasi stok saat offline disimpan di LocalQueue dan disinkronkan otomatis saat jaringan pulih.

STATUS: BELUM ADA ARTEFAK (EMPTY STATE)

Direktori Spesifikasi Masih Kosong

Belum ada file docs/PRD.md, tasks/*/plan.md, atau docs/design.md di ruang kerja ini. Viserys menahan agent agar tidak menulis kode aplikasi sebelum dokumen spesifikasi dibuat.

GERBANG VALIDASI MENOLAK EKSEKUSI (ERROR STATE)

Kriteria Verifikasi Belum Terpenuhi

Validator mendeteksi bahwa tasks/inventory/task-02.md masih berstatus Blocked by Task 01 (Database Schema) dan belum memiliki skrip pengujian yang lulus.

Solusi: Selesaikan Task 01 terlebih dahulu atau klik tombol di bawah untuk memulihkan artefak yang valid.
